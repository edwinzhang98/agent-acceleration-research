# 第三部分独立演示大纲 第二版

2026 年 10 月 1 日 · 供敲定内容后制作 Slides

这份演示讲清楚我们准备怎样研究 Agent 的环境探索与自我改进。面向有机器学习背景、未读过前两部分的听众，前两部分作为延展阅读。本稿保留两个完整方向：**主动探索环境，形成后续任务能用的知识与操作；从执行轨迹中学习，修改 Agent 自己的做法。** 两个方向先分别实验，再研究相互配合。

正文共 **12 页，第 1 页兼作封面**；完整参考文献和细节附录另列。每页“上屏内容”是拟议正文，“图示与讲述”说明怎样把内容讲具体，“制作依据”保存来源和必要边界，不整段搬上屏。本稿用中文审阅，正式 Slides 沿用已有演示的英文页面约定。

## 第 1 页 我们要做什么

**建议标题：** 面向重复工作流的 Agent 探索与自我改进

**上屏内容：**

我们研究重复发生的企业网页任务：Agent 能否利用过去获得的知识与经验，在满足任务正确性要求的前提下，让后续执行更快、累计费用更低？

- 探索环境：主动交互，学习功能、操作条件和行为规律。
- 从执行轨迹学习：分析失败与低效执行，修改提示、工具或执行流程。
- 首轮计划固定模型权重，以费用填报为应用例子。时间与费用分别评估，学习投入也计入。

**图示与讲述：** 一条连续任务带：同一应用内，票据和任务参数不断变化。下方标出两条学习路线。说明这是拟议研究目标，尚无本项目的实验收益；固定权重是首轮研究设置。

**制作依据：** [问题定义](2026-09-30-agent-acceleration-problem-framing-zh.md)与[最新相关工作分析](2026-10-01-agent-acceleration-related-work-analysis-zh.md)。这里给项目定位，不把重复任务或固定模型定义成整个 Agent 加速领域的范围。

## 第 2 页 一次费用填报中哪些工作会重复

**上屏内容：**

同一应用内，Agent 需要理解输入、找到页面、填写字段、执行操作并检查结果。

- 换一张票据，部分页面路径、字段关系和操作流程可能仍然适用。
- 当前票据怎样归类、信息是否完整，仍需要结合任务判断。
- 过去成功的操作可能包含绕路，也可能因页面或规则变化而失效。
- 先测时间花在模型、观察、工具等待还是返工，再判断哪些工作值得学习和复用。

**图示与讲述：** 用同一条填报流程标出“可能稳定的部分”和“随任务变化的部分”，不预先标任何节省比例。贯穿例子采用“切换费用类别后，必填字段发生变化”：它既可以是主动探索的对象，也可以从一次漏填返工中被发现。该规则仅为示例，具体应用中的行为需要实测。

**制作依据：** 这是本项目的拟议场景与测量计划。一般动机参考 [Grounding Agent Memory](#ref-grounding) 对重复发现环境信息的讨论，以及 [Growing Harness](#ref-growing) 对重复控制决策的讨论。两篇论文不能代替我们对目标工作流的瓶颈测量。

## 第 3 页 环境探索与轨迹学习怎样配合

**上屏内容：**

| 方向 | 主要过程 | 留给后续任务什么 |
|---|---|---|
| 探索环境 | 主动提出问题、尝试操作、核对反馈 | 环境说明、条件规则、页面关系或可调用工具 |
| 从执行轨迹学习改进自己 | 分析执行记录、定位问题、提出修改、重测 | 更新后的提示、记忆、工具或控制流程 |

探索产生的轨迹可以帮助改进系统；执行记录中的疑问也可以触发新的探索。两个方向可以独立研究，产物与实现可能重叠。

**图示与讲述：** 画两条并列流程，分别连接到后续任务执行。中间仅标出“提供轨迹”和“提出待探索问题”两条联系。探索既可发生在正式任务前，也可发生在任务之间；不把它画成只能给已有技能做检查的附属环节。

**制作依据：** [最新分析的两方向说明](2026-10-01-agent-acceleration-related-work-analysis-zh.md)。[Grounding Agent Memory](#ref-grounding) 是交叉实例：从轨迹提出候选经验，再查询环境核实并更新记忆。它说明两方向可以结合，不能据此声称所有系统修改都已实现，也不能把“两方向结合”本身作为新贡献。

## 第 4 页 方向一 主动探索环境并形成可用知识

**上屏内容：**

1. 根据应用入口、已有说明和任务需求，找出尚不清楚的功能或操作条件。
2. 设计练习和交互，观察不同输入、状态与操作带来的结果。
3. 从反馈中形成候选规则或操作，换条件验证，记录适用范围。
4. 保存为文字说明、条件规则、页面关系或可调用工具，供后续任务使用。

拟议例子：尝试不同费用类别，弄清必填字段怎样变化，形成带条件的填写操作。

**图示与讲述：** 按“输入、探索过程、产物、后续使用”展开一条完整流程。右侧给一份具体产物示意：操作名称、输入参数、适用条件、执行后应出现的状态、证据来源。文字知识与程序工具都保留；是否写成代码取决于能否验证和复用，不预设代码总更省。

**制作依据：** 流程是本项目拟议框架；[SkillWeaver](#ref-skillweaver) 与 [WALT](#ref-walt) 提供主动练习、探索和工具构建的参考。一次交互只能形成候选判断，不能自动提升为普遍业务规则。费用填报示例不是论文结果。

## 第 5 页 环境探索的相关研究与候选问题

**上屏内容：**

| 相关工作 | 已有做法 | 需要保留的条件 |
|---|---|---|
| SkillWeaver | 自拟练习，执行后生成并测试技能 | 成功率改善不代表已证明提速；技能检查会误判 |
| WALT | 探索网站功能，构建并测试高层工具 | 已报告构建费用；简化回本不等于完整净收益 |
| Grounding Agent Memory | 根据轨迹补查环境，核实后更新记忆 | 执行者费用未覆盖全部整理与探测开销 |

我们拟进一步比较：探索什么、怎样验证发现，以及怎样让知识在后续任务中有效复用。首轮选择其中一个具体机制检验。

**图示与讲述：** 使用三行方法比较，不放调研篇数。SkillWeaver 和 WALT 解释独立探索如何建立能力；Grounding Agent Memory 解释如何围绕运行中出现的疑问继续探索。明确哪些基础能力可以借用，再解释我们计划比较的具体做法；不把“别人少报一个指标”直接写成算法贡献。

**制作依据：** [SkillWeaver](#ref-skillweaver)、[WALT](#ref-walt)、[Grounding Agent Memory](#ref-grounding)，以及[逐篇比较](2026-10-01-agent-acceleration-paper-comparisons-zh.md)。WALT 的费用说明以补读的 ICLR 正式版为准；本页不引用跨条件的加速倍数。探索选择、停止条件和变化后复查均为候选问题，不替代完整的环境探索方向。

## 第 6 页 环境探索的第一轮实验

**上屏内容：**

研究问题：探索获得的知识，能否帮助未参与探索的任务，并收回探索投入？

- 固定执行模型、提示与控制流程，允许使用探索产出的知识或工具。
- 比较原系统、等预算的普通执行，以及已有探索方法和我们的候选做法。
- 测同流程换参数、新任务组合和明确环境变化；先在同一应用内开展。
- 观察成功率、实际耗时和累计费用。若收益只限于探索过的题，或复用收益不足以覆盖探索与维护，就调整当前做法。

**图示与讲述：** 展示实验的先后顺序：探索与开发阶段、冻结成果后的独立任务测试、环境变化测试。旁边用“前期投入、后续单任务开销、累计费用、任务质量”说明计划怎样比较收益。有实测数据后再画累计费用曲线，不用假数据或空坐标图占据当前页面。

**制作依据：** [最新分析的实验设置](2026-10-01-agent-acceleration-related-work-analysis-zh.md)。第一层实验检验探索在目标场景是否有用；第二层与已有完整方法比较，检验新增机制的价值。为比较探索策略，保持初始信息和环境访问预算可比；与普通执行者比较时另做等总费用对照。模型、权限及评测任务一致，预算差异如实记录，不用 token 近似相等冒充费用严格相等。

## 第 7 页 方向二 从执行轨迹中学习并修改自己

**上屏内容：**

执行轨迹（trajectory）记录 Agent 看到什么、怎样决策、调用了什么工具，以及结果和开销。

1. 收集失败轨迹，也收集成功但低效的轨迹。
2. 找出反复问题及可能原因，选择修改提示、记忆、工具或控制流程。
3. 产生候选修改，在开发和筛选用例中重测，检查收益和旧能力退步。
4. 保留有效版本，用于后续任务，再积累新的反馈。

拟议例子：反复漏填返工促使系统增加字段检查，并验证修改是否有效。

**图示与讲述：** 按与第 4 页相同的“输入、学习过程、产物、后续使用”结构画循环。示例展示“原轨迹的问题、拟修改的位置、修改后的重测”三段。首轮可以只支持提示和一种工具或流程修改，但方向范围仍包括从轨迹改进整个模型外部系统。模型给出的原因是待验证解释，改动后的对照结果才用于判断是否保留。

**制作依据：** [HarnessFix](#ref-harnessfix)、[Growing Harness](#ref-growing)、[SpeedRunner](#ref-speedrunner)。本页是拟议流程，不表示这些论文都实施同样的独立验收。如何给问题排序、怎样发现成功轨迹中的浪费，是这个方向中的候选机制，不代表整个方向。

## 第 8 页 轨迹学习的相关研究与候选问题

**上屏内容：**

| 相关工作 | 已有做法 | 需要保留的条件 |
|---|---|---|
| HarnessFix | 从失败轨迹定位并修补框架，检查旧任务退步 | 可靠性改善不能直接当作部署提速 |
| Growing Harness | 根据轨迹修改共享代码，减少重复模型决策 | 部署费用不含离线优化；部分设置质量有下降 |
| SpeedRunner | 从执行反馈增删改程序技能 | API 账含部分学习摊销；未证明实际耗时下降 |

我们拟进一步比较：怎样识别值得修改的问题、选择修改方式，并验证后续收益。成功但浪费的执行也纳入研究。

**图示与讲述：** 保持与第 5 页一致的三行结构。依次解释“定位问题”“改变执行方式”“根据持续反馈修改技能”。指出已有自动改进能力可以作为实验起点；我们需要证明新增方法比这些起点更有效，不能仅以存在自动循环作为贡献。

**制作依据：** [HarnessFix](#ref-harnessfix)、[Growing Harness](#ref-growing)、[SpeedRunner](#ref-speedrunner)。SpeedRunner 已核对版本的 API 费用包含执行者和摊销后的技能归纳者，不能写成完全漏算学习。Growing Harness 的质量与费用结果需绑定具体设置，不概括为所有条件都保持质量。[ClawTrace](#ref-clawtrace) 放附录，作为成功轨迹中修错和删减浪费的额外比较。

## 第 9 页 轨迹学习的第一轮实验

**上屏内容：**

研究问题：自动分析和修改，能否改善后续任务，且收益足以覆盖改进投入？

- 从相同初始 Agent 和环境知识出发，首轮不额外加入主动探索模块。
- 比较原系统、简单轨迹经验总结、已有修改方法和我们的候选做法。
- 使用同一批初始轨迹和可比改进预算，分别检查失败修复、成功任务提效和旧任务退步。
- 若要判断某个新环节是否有贡献，固定其他环节再比较；简单方法已达到相同收益时，不继续增加复杂度。

**图示与讲述：** 用一张实验图展示共同起点与不同改进方法；后续分别生成的轨迹按同一采样规则计入预算。图的输出端标出计划比较的“修改后质量、运行开销、学习投入与累计费用”。单次失败或未获收益用于调整当前机制，不直接否定整个研究方向。

**制作依据：** [最新分析的实验设置](2026-10-01-agent-acceleration-related-work-analysis-zh.md)。所有组使用相同任务划分、工具权限与允许反馈；保留相关方法原有的检查和恢复能力。“原系统”另给相同总费用，用于增加合理执行或重试。若研究问题排序，应固定编辑器和验收器，再比较失败频次、简单频次乘损失以及候选排序；这只是可能的后续实验，不是已确定算法。

## 第 10 页 正确性与收益的统一评测

**上屏内容：**

- 独立判对错：书面规则生成用例和答案，经人确认；检查结果、字段及不应发生的状态变化。
- 分开发、筛选与最终测试。标准答案只供评分，改进循环不能修改规则或评分器。
- 时间与费用分别报，同时报告任务质量。调用数、步数和 token 用来解释机制。
- 执行、失败回退、探索学习及必要维护各计一次；研究测评另列。冻结成果测泛化，固定更新规则测持续学习。

**图示与讲述：** 评分系统放在两个学习循环之外。用两个平行实验框区分“冻结学习成果”和“持续适应”。费用图展示业务执行与学习维护的累计总额，研究专用测评费用单列；时间图测用户实际等待，不把并行模块耗时直接相加。

**制作依据与评测约定：**

- 按开发任务生成经验和候选修改，用筛选任务选择版本，最终任务不参与方法或参数选择。开发可读取允许的判错反馈，标准答案不作为经验输入。
- 持续学习实验固定更新算法与参数，使用相同任务顺序和可见反馈规则；每项任务先记录表现，再允许按规则更新，隐藏答案不回流。业务规则变化建立新的评分版本，更新不能由被评测 Agent 决定。
- 先约定质量要求和必须满足的执行约束，再比较时间与费用；出现更快但更贵等情况时分别展示，不临时加权成一个得分。具体质量阈值及主指标在试点测量后预先写入实验协议。
- 净运行收益包括实际需要的探索、改进、准入验证、维护及失败开销。只为研究比较而开展的额外测评单列，避免与改进过程必须发生的验证混淆。纯研究预算仍需在资源页计入。
- 重复运行并报告波动，抽样人工复核评分。参考 [AppWorld](#ref-appworld)、[AI Agents That Matter](#ref-agents-matter)及[预算对照研究](#ref-budget-study)。细节放附录，不在正文展开评测术语。

## 第 11 页 实验推进与两个方向的组合

**上屏内容：**

| 阶段 | 主要工作与交付物 |
|---|---|
| 准备 | 可重置流程、独立评分和完整日志；测出主要耗时与费用来源 |
| 分别验证 | 环境探索和轨迹改进各做最小实验；确定有效范围与主要失败原因 |
| 组合验证 | 比较原系统、仅探索、仅轨迹改进、两者结合，检查额外收益 |
| 持续运行 | 测任务变化、规则变化与维护，判断收益能否持续 |

每阶段依据质量、实际节省和投入决定继续或调整。组合有效后再扩大范围。

**图示与讲述：** 两个方向从同一个测量与评测基础并列出发，之后汇合。结合方式仍用填报例子：执行记录暴露字段依赖不清，触发定向探索；经过验证的规则帮助修改填写流程。组合实验对齐总预算，避免把更多投入当成模块配合的收益。

**制作依据：** 本项目拟议计划。对独立有价值或明确互补的机制再做组合，不承诺两条路线都产生新算法。如果瓶颈主要是无法通过学习减少的外部等待，应调整优化对象。是否训练小编辑模型另列附录，首轮不扩展到模型训练。
