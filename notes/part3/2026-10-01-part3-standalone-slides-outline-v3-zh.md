## 1. 主线

沿用第一、二部分已有的公式和符号，不另起一套。第三部分只新增三个符号：$m'$、$T_{\text{setup}}$ 和 $n^*$。

| 公式 | 含义 | 出处 |
|---|---|---|
| $v(m,p)=\dfrac{C_m(p)}{R_m(p)}$，$T_{\text{success}}(m,p)=\dfrac{\mathbb{E}[T_{\text{attempt}}]}{R_m(p)}$ | 设计 $m$（模型 + 外围程序）做任务 $p$，每次成功的美元和秒数 | 第一部分第 2 页；Erol et al., 2026（Cost-of-Pass，ICLR 2026） |
| $v_n(m',p)=\dfrac{C_{\text{setup}}}{n}+\dfrac{C_{m'}(p)}{R_{m'}(p)}$ | $m'$ 是同一个模型、外围程序经学习改过的设计；学习花费 $C_{\text{setup}}$ 摊到它服务的 $n$ 个任务上 | 第二部分附录 B8；固定成本加可变成本见 Kapoor et al., 2025 §3；一次准备、$n$ 次运行见 LATM（Cai et al., 2024） |
| $\min\big(T_{\text{success}}(m',p),\,v_n(m',p)\big)$，约束 $R_{m'}(p)\ge R_0$ | 第一部分的目标，计入准备成本；成功率在没参与学习的任务上测 | 第一部分第 2 页；$R_0$ 为自定 |
| $n^*=\dfrac{C_{\text{setup}}}{v(m,p)-v(m',p)}$ | 回本点：做完多少个任务后，学习花费被省下的钱抵消 | 由上面第二行推出（calc.）；Kapoor et al., 2025 §3.2 做的是同一种比较（联合优化在约 1,350 个任务后总成本更低） |

符号约定（同第一部分）：

- $m$ = 设计（模型 + 外围程序），$p$ = 任务；
- $N$、$i$、$j$ 是一次尝试内的步数、第几步、第几次调用，第三部分不用来表示任务；
- $n$ = 任务数，同第二部分。

**$C_{\text{setup}}$ 的范围：** 探索、生成修改、验证，以及维护，各计一次。第二部分附录 B8 原来的写法是“一次性构建成本”。为了前后一致，这次把那里的定义一并改成“一次构建，以及在论文报告了的情况下的维护”。B8 表里各篇的数字不变，因为这些论文都只报了一次性构建。

**时间：** 用户等待用第一部分的 $T_{\text{success}}$。离线学习工期记为 $T_{\text{setup}}$（自定），单独报，不摊到任务上。问题定义 §一里的第三项“计算资源占用”目前没上页面。

**各段和公式的关系：**

- 第一段（问题）：把每一项讲清楚；
- 第二段（现有研究）：两个方向都想降 $C_{m'}(p)$，代价是 $C_{\text{setup}}$，同时 $R_{m'}(p)\ge R_0$ 要守住；
- 第三段（计划）：待讨论。

## 3. 第一段：问题（第 1–4 页）

### 第 1 页　The problem: the same workflow with new inputs, in less time and for less money at the same success rate

- **结论：** 同一流程、每次输入不同的任务，靠学习改外围程序、模型不动。学到的设计在计入准备成本之后，每个任务更快、更省，并且成功率不低于事先定的下限，才算划算。
- **公式：** §1 表格的四行，每行在页面上都注明出处。下面另列 $C_{\text{setup}}$ 和 $T_{\text{setup}}$ 的含义。
- **卡片：**
  1. **学习的花费要算进去。** 例子：ActionEngine 每个任务 27 s 对 87 s、$0.05 对 $0.40，但这两个数不含探索和预热；把探索算进去，要 39–101 个任务才回本，而且仍未计预热（WebArena 655 题，Claude Opus 4.6，对照 Claude Code；附表 L558）。
  2. **第一版固定模型权重**，只改提示、记忆、技能与工具、控制代码。这是实验范围，不是“加速”的普遍定义。
- **附录：** A1。

### 第 2 页　Where one expense report loses time

- **结论：** 一次报销里，有些步骤是必要的交互，有些是重复摸索和返工；后者是可以学掉的部分。
- **图：** 一条示意操作记录：
  - 新建报销单 → 选费用类型“酒店” → 上传票据 → 提交 → 报错“缺少入住和离店日期” → 补填 → 再提交 → 核对已保存。
  - 返工的三步标橙色。
  - 页面上写明：“示意；环境尚未选定，规则为虚构。”
- **定义栏，四个词，每个一句：**
  - 任务：目标、输入数据、初始状态，以及外部的成功检查；
  - 环境：网站的界面、规则和允许的操作；
  - 运行记录：一次执行的观察、动作、反馈、结果、时间和费用；
  - 学习：跨任务保留的、改模型外部的更新，即提示、记忆、技能与工具、控制代码，模型权重不变。
- **数字：** 无。这一页是示意，不放数字。
- **来源：** v2 第 2、5 页的定义与图，例子换成报销单。

## 4. 第二段：现有研究做到哪（第 5–10 页）

### 统计口径

后三列的判定见 [逐篇判定](2026-10-01-part3-coverage-judgments-zh.md)。这些判定是本会话根据附表单元格做的初判（calc.），未回读全文；做页前对代表工作逐篇复核。

- **执行时间/费用：** 是 = 实测了执行任务的秒数或美元；部分 = 只有 token、步数、调用数或作者估计。
- **学习投入：** 是 = 实测了学习、构建、维护的 token、美元、时间、算力或 rollout 数之一；部分 = 只有估计、迭代数，或明确漏掉一部分。
- **没见过的任务：** 是 = 在没参与学习或挑选的任务上测；部分 = 在线任务流、同一流程换参数，或划分没交代清。

**附表后段自由写法类别的归并：**

- 方向一：
  - 框架、效率导向框架、代码规划与调度 → 整体框架；
  - 技能、工具、快捷动作、重放技能、接口技能、轨迹编译、工作流维护、费用归因与技能文档、执行加速 → 技能与工具；
  - 记忆 → 经验记忆；
  - 提示词错误归类 → 提示与上下文；
  - 在线增强成本对照 → 经验记忆和技能与工具各计一次。
- 方向二：
  - 应用文档、内部接口规则、前提、可检查前提、探查事实、文字经验 → 文字说明、事实与前提；
  - 页面结构、网站模板、地点结构 → 页面与地点结构；
  - 探索、应用探索 → 主动探索与练习。
- 方向二正文合并成 4 行：
  - 工具说明（§3.2）与文字事实（§3.5）都是“可读的说明”，合为一行；

### 第 6 页 方向一机制：一条运行记录怎样变成一次修改

- **图：** 运行记录 → 找失败和浪费，定位到步骤和代码位置 → 提出修改（提示／记忆／技能／代码四个落点）→ 在验证任务上重测，并查旧任务有没有退化 → 留下或撤回。标出三处花钱的地方：诊断、生成候选、重测。
- **卡片 1：** **修改能自动做出来，也有留出收益。** HarnessFix：完成率提高 6.3–18.4 个百分点，AppWorld 离线修补 37.2M token，执行阶段的时间和费用未报（L562）。
- **卡片 2：** **省下的执行费常常不含学习侧的花费。** Growing Harness：部署时的推理费用降低 74.4–98.6%，但不含评估者和离线优化者的开销，也没测回本（BrowseComp-Plus 和 WebArena-Verified，三种模型，每组 50 个最终任务、3 次运行；L566）。
- **代表的选法：** HarnessFix 是预印本。它是附表里和“读记录 → 定位 → 修 → 回归检查”这条链最一致的工作；主会里的框架类工作都不读运行记录做诊断。

### 第 9 页 两个方向共同的问题和矛盾

四张卡片，依据文献文档 §5，每张一个例子：

1. **很少有人同时算学了花多少、省了多少。** 102 项里，只有 5 项既实测了执行时间或费用，又实测了学习投入：GPTSwarm、MobileGPT、OpenSkill、EchoPath、Unbrowse（初判，calc.）。
2. **证明改对了、又没弄坏旧能力，是关键难点。** 模型当裁判会把失败判成成功；不报错、能编译也不等于做对。AgentDevel 的消融显示，最高平均分和更少的旧任务退化之间可能要取舍（Zhang, 2026）。
3. **步数少不等于更快更省。** ReasoningBank 的平均步数 9.7 → 8.3，但另一张表里总 token 50,847 → 53,055（底座未注明；Ouyang et al., 2026）。
4. **学到的东西换个环境不一定还省。** ClawTrace 迁移到 SkillsBench，每题费用中位数 $0.143 对 $0.144，没有下降（Yuan et al., 2026）。
