### 0.3 Measurement-definition rules (ChatGPT's discipline, adopted here)

These distinctions decide whether a number supports the thesis. They are applied to every entry below.

1. **Model calls ≠ tool calls ≠ environment steps ≠ turns.** OSWorld 2.0 reports tool calls and steps separately (batched tools make several calls per step). GTA1 makes 4–12 planning calls per judging call. TheAgentCompany defines "steps" as LLM calls.
2. **Model-inference time ≠ end-to-end wall-clock.** The widely quoted "225–330 s per task" product comparison is pure LLM inference time per trajectory, not task time (verified, D1).
3. **Cost per attempted task ≠ cost per successful task.** $72.4/attempt at 20.6% completion ≈ $351 per observed success (calc.), but that is an accounting ratio, not the price of retrying one task until it works.
4. **Human "estimates" ≠ stopwatch trials.** OSWorld-Human's "<30 s" is the authors' estimate; OSWorld 2.0's "1.6 h" is an annotator-recorded estimate from people who performed the task (verified, D2).
5. **Version matters.** Several headline numbers changed between arXiv versions (OSWorld-Human step ratio, PASTE, Continuum, FocusAgent, Efficient Agents). Cite the version.

## 0.4 Executive synthesis (what the 15 reports jointly establish)

1. **Where the time goes depends on the agent architecture — there are three regimes, not one bottleneck.** Screenshot-based multi-call desktop agents without effective caching (OSWorld-Human) spend 87–97% of wall-clock in LLM planning/judging/reflection and are prefill-bound, with later steps up to 3× slower. Text/AXTree single-call web agents (BrowserGym, Skim) spend 50–62% of step time in the browser. Cached coding agents (TraceLab, Agentic AI Workload Characterization) see 85–99.5% cache hits, decode-dominated LLM time, and a heavy tool-latency tail (4% of tool calls = 85% of tool time). All three regimes appear across the inputs; only ChatGPT's P1 report noted the tension explicitly. Details in §1.8.
2. **The marginal cost of accuracy is steeply convex at the frontier.** OSWorld 2.0: 13.0%→20.6% completion costs ~6× output tokens (37.1K→224K/task; ~$25.5→$72.4/task), "roughly 25 to 30K extra tokens for each additional point" [V]. HAL: 9× cost for 2 points on Online-Mind2Web. Agentic Test-Time Scaling for WebAgents: 9.6× tokens for +4.4 points with the model held fixed. Three independent measurements, one shape.
3. **For interactive deployment, turns are the cost that matters, not tokens.** OSWorld 2.0 states this explicitly and shows the token-ranking inverts in turn space (Opus 4.8: most tokens, fewest turns via batching) [V]. Its protocol also inserts a 3-second pause after every action, so a 150–600-tool-call trajectory carries 7–30 minutes of forced waiting before any inference time (calc.).
4. **Fewer model calls does not imply faster.** AWO/meta-tools: calls fall 21.8→19.2 but time rises 75.6→88.1 s with Claude; FocusAgent's retriever cuts tokens but raises per-step model latency 2.5→10.1 s; DSP cuts latency 37% but raises cost 63%; Interactive Speculative Planning cuts time 42% but raises cost 38%.
5. **"Lossless" has three distinct senses** (by-construction trajectory preservation; statistical non-inferiority; no observed degradation), and no surveyed acceleration paper runs a formal non-inferiority test. Only exact-match, read-only speculation (Speculative Actions, Speculate-with-Memory, PASTE audit) is lossless by construction.
6. **Demand is exploding and is now agent-dominated on the largest public router.** OpenRouter: agentic tokens overtook human tokens "right around February 1st" 2026; agentic requests use ~15× the tokens of human requests; 450T+ tokens analyzed Jan 1–Jun 14 2026 [V]; agentic tokens grew 14× in ~6 months vs 2.8× for human, but ~70% of agentic tokens are cached prompt tokens. Gartner (primary, 25 Mar 2026): agentic models need 5–30× tokens per task vs a chatbot, and "overall inference costs are expected to increase" even as unit prices fall >90% by 2030 [V].
7. **Survey evidence supports "latency constrains interaction design and which tasks get deployed," not "latency blocks deployment."** LangChain: latency is the #2 production barrier (20%, N=1,340). MAP (peer-reviewed): only 14.8% of deployed teams call latency critical; 15/20 systems run asynchronously. Temporal: 79.8% say operating cost is a meaningful factor, yet 91.1% report productivity gains.
8. **Vendors are monetizing speed.** Anthropic and OpenAI both sell "fast mode" at up to 2.5× output speed for 2× price; Microsoft excludes >128k-token prompts from its priority tier; Google moved computer use into Flash/Flash-Lite; Anthropic switched Claude in Chrome's default to Haiku 4.5 for responsiveness.
9. **Landscape (8 families):** the largest measured gains come from eliminating calls outright (compiled GUI programs: Agent JIT 9.7×, AutoDroid-V2 −93% inference time, GPA 329→34 s), exact KV reuse and program-level scheduling in serving (SGLang 6.4×, Autellix/Agentix 4–15×, Continuum v7 1.1–3.7×), and parallel tool dispatch (LLMCompiler 3.74×). Lossless action speculation delivers ~20–45% (and Speculative Actions proves a **50% cap for single-step speculation** [C15]). Observation compression and routing help but usually trade accuracy. Doc 15 sharpens this into a ranking: **call-count reducers (executable skills, site-derived tools, native APIs) are the one family that is both large and accuracy-positive** (ASI +23.5% rel., WALT 50.1% WebArena, ComputerRL ≤1/3 the steps and +134% rel., AXIS −65–70% task time), whereas text-only workflow memory does not reliably save steps (in ASI's controlled re-run AWM used 5.9 steps vs 5.6 for vanilla). Practitioner stacking order: lossless serving/caching/parallelism first, call-count reducers second, lossy per-step levers (routing, pruning, lower effort) last.
10. **Evaluation practice is weak:** single runs per configuration (HAL, Efficient Agents, Agentless), undated prices, emulated or inference-only latency, and "comparable accuracy" claims without margins. A first paper can differentiate by pairing a construction guarantee with a pre-registered paired non-inferiority test and by reporting wall-clock, calls, tokens, dollars and cost-of-pass together.
11. **Novelty for the SAP Concur plan:** every component exists (skill/recipe compilation, speculative actions, plan caching, pruning, routing, cost-Pareto evaluation), and five of the ten closest works are Apr–Sep 2026 preprints. What is still open: speculation over irreversible, non-snapshotable UI transitions with commit/compensation semantics; profile-guided recipe compilation with guarded de-optimization learned from own runs plus a few demos; and field-level, per-lever accuracy-loss attribution with three-way accuracy–latency–cost frontiers over repeated runs.
12. **Data hygiene:** several widely repeated numbers in the inputs are wrong, misattributed, or mis-defined (Part VI lists 55). The most consequential: the 225–330 s "task time" (inference time), "318 median tool calls" (mean, single-action Opus 4.7), Efficient Agents "$0.228/28.4%" (repeated by G9, G10 and C15), APC "0% degradation", the "MacroPO" paper (an AI-generated idea file), Gemini's attribution of OSWorld 2.0's marginal-token finding to an HPCA paper, and — added in v2 — FocusAgent's WebArena result flipping sign between v1 (−4.2 pp) and the TMLR revision (+3.1 pp) (D48), plus doc 15's claim that no controlled multi-action study exists on OSWorld, which UFO2 Table 7 and OSWorld 2.0 Table 3 contradict (D46).

Consequences for the thesis and for the user's paper:
- "Agents are too slow because inference is slow" is true for Regime A, half-true for C, and false for B. Any slide must state which regime a number comes from.
- OSWorld 2.0's turn-space result (batched Opus 4.8 reaches the best score in ~103 turns; single-action Sonnet 4.6/MiniMax need 250–325 turns for <10%) [V] means that **reducing environment turns is a first-class objective**, independent of tokens — this is exactly what compiled recipes and action batching attack.
- The forced 3-s pause per action in OSWorld 2.0's protocol, and OSWorld 2.0's "stale interface state" failure mode, show that latency is also an **accuracy** problem on dynamic UIs, not only a cost problem.

# PART II — Prompt 2: Mapping LLM inference optimizations onto agent workflows

## 2.1 Framing (what all three providers agree on)

At the inference level the optimization target is one request: TTFT (prefill-bound), TPOT (decode-bound), throughput per GPU. Autellix states the mismatch directly: request-level metrics overlook end-to-end latency for agentic programs [C]. At the agent level the unit is a **step** (one model call plus one or more tool/environment actions), repeated until termination, so

Cost(task) ≈ Σ_steps [ prefill(context_t) + decode(output_t) + tool_latency_t + queueing_t + orchestration_t ],

with context_t growing every step. ChatGPT's framing sharpens this: the objective moves from token generation to **the critical path of a successful task**, and "behavioral equivalence, comparable benchmark accuracy, and an accuracy–cost tradeoff are different claims" [O]. Gemini's framing adds the serving-side view: agent sessions hold KV/tool/environment state through long idle waits, so retention and eviction policy become first-order costs [G].

- *KV / prefix caching, exact →* KVCOMM (cross-agent KV reuse via anchor offset correction, up to 7.8×, "no loss reported") and DroidSpeak (KV sharing across fine-tuned variants, NSDI 2026, up to 4×) — both **approximate**, so they sit between exact reuse and lossy compression; InferCept's finding that KV recompute was 37–40% of forwarding time before interception-aware serving.
- *KV / prefix caching, semantic →* EchoPath (validated GUI trajectories as callable memories with preconditions and lifecycle states), AgentReuse (parameterized plan reuse, −93% latency on near-duplicate requests), ToolCaching (bandit-admission tool-result cache), AgentRR (record-and-replay proposal, no numbers).

- *Distillation / draft models →* Fara-7B vs OpenAI computer-use-preview ($0.025 vs $0.913/task), Step-level Optimization's config range (58.2–59.3% vs 60.1%).
- *Early exit / adaptive computation →* API-first and hybrid API+GUI action spaces (AXIS −65–70% task time; ComputerRL ≤1/3 steps; Beyond Browsing +24 pp) as the strongest form of "eliminate the decision"; The Danger of Overthinking (o1 low effort −43% cost, −1.8 pp), Budget Tracker/BATS (−31% cost at equal accuracy), TTI "Thinking vs Doing" (spend budget on actions, not per-step thinking; per-step budget forcing gave only ~3%).
- *Quantization →* Prune4Web (AAAI 2026; 25–50× fewer candidate elements, grounding 46.8→88.3%), ScreenSeekeR zoom-in as the counterexample that *adds* calls to buy accuracy (18.9→48.1%).

## 2.3 The cost-unit shift: from tokens to dependent decisions

Points that at least two providers made, with the strongest evidence for each:

1. **One environment step can contain several expensive model calls.** GTA1: 4–12 planning calls per judging call plus grounding; S2: planning + reflection + retrieval per step (E22, E25). TheAgentCompany counts LLM calls as steps by definition (E10). Consequently action count, model-call count and *sequential depth* must be measured separately [O, C].
2. **Production requests expand into mostly sequential inference chains.** Copilot: 6.6 model calls per user turn, concurrency 1.15 (E20). Claude Code/Codex: 8.8 LLM calls, 10.8 tool calls, 4.3 min per request (E19). So repeated request entry and dependency depth, not decode speed, set task latency [O, C].
3. **Growing context creates repeated logical input, but not necessarily repeated prefill.** OSWorld-Human's 3× later-step slowdown (uncached screenshot history) vs 84.6–99.5% cache hits and 91–98.6% decode share when KV state stays resident (E23, E29). "Agents are prefill-dominated" is not universal [O]. TraceLab's 95.7% hit rate still leaves prefix tokens as 59.5% of cost because of 3.8× prefill amplification on misses [C].
4. **Token prices are collapsing faster than task costs.** GPT-6 Luna at $0.10/$0.50 per M (Sept 2026) and DeepSeek V4 Flash at $0.09/$0.18 [V] make "saving a few thousand tokens" less valuable than "saving seconds of idle wait"; Gartner expects per-workflow inference cost to *rise* (E62) [G, C].
5. **Tool waits dominate in some workloads and are heavy-tailed** (4% of tool calls = 85% of tool time; tool execution 35–61% of request time) [C, G] — the strongest argument for serving-side KV retention and speculative tool execution.
6. **Turns are the deployment-relevant cost** for interactive use (OSWorld 2.0) [V] — the strongest argument for compiled recipes and action batching.

## 2.4 Context-growth accounting (derived independently by ChatGPT and Claude)

For N model calls with initial context H₀ and Δ new tokens per call, the submitted input volume is Σᵢ Hᵢ = N·H₀ + Δ·N(N−1)/2 with Hᵢ = H₀ + (i−1)Δ. Worked examples: 10K-token prefix over 50 steps = 500K prefix tokens alone [C]; 5K start + 500/call over 100 calls = 2.975M input tokens, average 29,750 per call [O]; Gemini's budget assumes 5K→45K linear growth, average 25K. Caching changes the constant, not the shape (reads 0.1× or less; TTFT −13–31% measured); context editing restores recomputation (SmoothAgent). For serial workflows task time accumulates queueing + prefill + decode + tools + orchestration across calls; for parallel execution the dependency graph's **critical path** governs completion, so summing overlapping call durations overstates end-to-end time [O]. Dollar accounting must keep uncached-input, cached-input, output/reasoning and tool charges separate.

## 2.5 Single-slide thesis (the three providers' versions, then a merged one)

- **ChatGPT:** Agent acceleration is inference optimization lifted to a stateful execution graph — speculate transitions, retain reusable computation, compile familiar routines, schedule independent work, allocate model capacity by decision difficulty; the objective is lower wall-clock and dollars per successful task at a specified reliability level; papers validate mechanisms separately and PASTE shows why integration matters (accelerating tools alone creates returning-request congestion).
- **Claude:** In agentic workloads the unit of cost is the step, not the token; each call re-prefills a growing context interleaved with heavy-tailed tool latency; every classic inference optimization has a step-level twin; the largest verified gains (2–15× serving throughput, 30–70% fewer steps or cost) come from treating the agent *program* as the unit to schedule, cache and prune; the next frontier is step-level accounting plus verifiers that know when a cheaper step is safe.
- **Gemini:** The unit has shifted from tokens to stateful multi-turn steps; because agent workloads achieve 85–99% KV-cache hit rates while spending up to ~60% of their lifecycle waiting on sandboxes and tools, prefill-focused acceleration has diminishing returns; treat the LLM as the CPU of a distributed system and map micro-level techniques to the macro level.
- **Claude (P3 survey, doc 15):** The quickest way to make web, GUI and computer-use agents faster and cheaper is to cut the number and size of LLM calls, not to speed up each call; the methods that reduce calls (executable skills, site-derived tools, native APIs) lose the least accuracy and usually raise it; serving-layer KV reuse and provider caching are free; speculation is lossless but capped near 50% per step and untested on irreversible GUI clicks; the field's main weakness is measurement on incompatible benchmarks. Practitioner order: lossless layers first, call-count reducers second, lossy levers last and per-step.
- **Merged (recommended):** *Agents are programs, not prompts. Their cost is a critical path of dependent model calls over a growing context, interleaved with heavy-tailed tool waits; which term dominates depends on the observation modality and caching (three regimes). Every inference optimization has a step-level twin — speculate transitions, retain KV and reuse plans, batch and schedule at program level, route steps to small models, compile determined steps away, compress what is re-read — and the largest verified wins come from removing sequential decisions and environment turns, not from faster tokens. The levers stack in a definite order: lossless serving, caching and parallelism first (free), call-count reducers second (usually accuracy-positive), lossy per-step levers last. The research objective is wall-clock and dollars per successful task at a stated reliability, measured with calls, turns, tokens and tool time reported together.*

## 3.9 What remains open (merged across the three surveys)

1. **Safe abstraction and invalidation.** When does a compiled skill/recipe/cached plan still apply after UI, data or permission changes? Precondition validation, drift detection and safe return to observation are unsolved; today's fallback is reactive failure [O, G].
2. **Full lifecycle economics.** Demonstrations, exploration, compilation, training, warm-up, verification and repair are real costs; reuse pays only after amortization (PreAct's +162–217% verify overhead; SpeedRunner's growing library cost; break-even estimates like Compiled AI's ~17 transactions) [O, C].
3. **Joint control.** Model choice, reasoning effort, screenshot detail, action-chunk length and speculation depth interact; savings can cancel (pruning breaks caches; routers/verifiers eat latency; speculation raises API cost). Individual speedups must not be multiplied [O, C].
4. **Real GUI speculation.** Shared state, rollback, asynchronous updates and irreversible effects limit which branches can be pre-executed; snapshot/fork substrates (TClone, DeltaBox, SMC) do not exist for live SaaS [O, C, G].
5. **End-to-end evidence and non-inferiority.** Held-out long workflows, paired outcomes, uncertainty, deadlines and recovery; grounding scores and successful-only latency are insufficient; equal point estimates are weak evidence [O].
6. **Serving–agent co-design.** Expose dependencies and likely tool-wait times to runtimes; account for tool rate limits, multi-user load, tail latency, and the residency-vs-batch-size conflict [O, G].
7. **Macro-action boundary detection and credit assignment**; mid-chunk interruption signals; scaling hybrid GUI+CLI wrappers across apps [G].
8. **Difficulty estimation before attempting the task** (chicken-and-egg for budget routing); high-variance RL rewards over long near-deterministic sequences [G].
9. **Observation completeness vs cost** — pruned pages lose context needed for recovery ("semantic error within a state"); observation freshness vs call frequency [G].
10. **Standard accounting unit** — none of the works proposes a standard "model calls per solved task + prefill tokens per task + turns + tool time" unit; this is a gap a paper can fill [C]. Doc 15 adds that no study compares families (skills vs APIs vs speculation vs routing) on one benchmark with shared cost accounting; WES and cost-of-pass are the leading candidates for a standard [C15].
11. **Replay under drift and cache poisoning** — skills, caches and compiled workflows run deterministically, so stale or wrong entries act without LLM oversight; EchoPath's lifecycle management (promote / repair / quarantine) is the most developed answer, but **no work measures replay success across UI versions over time**; poisoning of shared caches is unstudied while key-collision attacks on semantic caches already exist ([arXiv 2601.23088](https://arxiv.org/html/2601.23088v1)) [C15].
12. **Joint thinking- and action-budget control** — research treats the reasoning budget (Ares, TAB, Overthinking) and the action budget (BATS, TTI) separately; learned effort routers have only been shown on small open models; vendor effort knobs lack same-model ablations on agent benchmarks [C15].
13. **Whole-stack measurement** — no paper has measured the full stack (lossless serving + call-count reducers + lossy per-step levers) end to end on a computer-use benchmark with dollars and wall-clock; "whoever does will likely set the field's next reference point" [C15] — this is the opening the Part V plan can take.

## 4.2 What "lossless" should mean (three senses, merged)

1. **Behavioral preservation by construction.** The authoritative model's decisions are unchanged; speculative results commit only on exact match of action type and all arguments; incorrect work cannot alter externally visible state (read-only whitelist, isolation, rollback, semantic guards; Atomix-style epochs and sealed transactions; Spork-style KV forking). State the assumptions: deterministic/replayable observations, cache freshness, resource contention, and that "lossless" means preserving the *baseline agent's behavior*, not task correctness. Examples: Speculative Actions, Speculate-with-Memory, PASTE (with audit), ISP's exact OpenAGI mode; ISP's fuzzy TravelPlanner mode explicitly loses the guarantee [O, C, G].
2. **Statistical non-inferiority.** Task success or field accuracy may differ, but a pre-specified one-sided confidence bound excludes degradation beyond δ. This is "non-inferior within δ points", not losslessness [O, C].
3. **No observed degradation.** Equal or slightly better point estimates ("comparable accuracy", "96.7% of OWL", "not statistically significant"). This establishes neither of the above [O, C].

Corollaries: a replay completing every action is not proof the requested fields are correct (PreAct documents 100% coverage with evaluator score zero); equal final answers do not prove equal policy compliance or absence of side effects; a web-agent answer key should check requested values **and** state invariants [O]. Gemini's stricter operational definition — final trajectory, state transitions and environmental side effects "mathematically, semantically and observably identical" — is sense 1 plus an invariants audit [G].

## 4.3 Recommended protocol for the first paper (unified)

**Design.** 25 held-out tasks spanning several workflow families and horizons, selected by a documented stratified procedure (not baseline successes); separate development tasks; split by workflow template to avoid near-duplicate leakage. 6 conditions (unchanged agent; simple batched-action baseline; full method; 3 pre-declared ablations) × 3 models × 3 repeats = **1,350 episodes**, ~100 model calls each. Pair every accelerated run with the baseline on the same task/model/repeat index; freeze tasks, evaluator, normalizers, margins and exclusion rules in a timestamped pre-registration [O, C].

**Primary metrics.** (1) Per-field accuracy: micro and macro F1 over normalized fields (exact identifiers; canonical dates/units; numeric tolerance; list-order rules); macro averages fields within a task then tasks so a 100-field form does not dominate a 5-field one; report missing / incorrect / extra / critical-field errors separately; LLM-judge with rubric trees only for free-text fields, with judge–human agreement (κ) on a sample [C, O, G]. (2) Strict task success: all required fields, all required actions committed, all invariants satisfied. (3) End-to-end wall-clock: request accepted → final committed state; mean, median, p90/p95 with uncertainty; **success-within-time curves** and a deadline-adjusted time (failures assigned the common deadline H) so fast failures cannot look like wins [O].

**Secondary metrics.** pass^1, pass^3 (all three pass), pass@3 (any), per-task outcome matrix; model calls split by role (actor/planner, draft, verifier, compressor, memory builder, retries) plus critical-path sequential depth; environment actions, tool RPCs, screenshots; tokens by class (input, cache read, cache write, visible output, billable reasoning, image) with raw provider usage saved for re-pricing; dollars for all attempts incl. failed branches and auxiliary models, list-price-normalized and actual; cost-of-pass as the pooled ratio (total $ / successes) **and** the taskwise average of C_i/p_i (flagged as unstable with 3 trials; undefined if zero successes); mechanism metrics (acceptance/cache-hit/fallback rates, wasted speculative work, call reduction, context growth, side-effect/invariant violations); optionally VAF and GDS [O, C, G].

**Lossless claims.** Tier 1 (construction): exact-match commit, read-only whitelist, logged commits/rollbacks, and a trajectory-equivalence audit with actor outputs held fixed (replay or cached temperature-0 responses) requiring byte-identical action sequences and final answers in 100% of runs. Tier 2 (outcome, live): H₀: F1_accel − F1_base ≤ −δ with δ pre-registered (Claude proposes 5 pp on field F1; ChatGPT proposes 2 pp on strict success and 1 pp on macro field accuracy, both gates required); task-level paired differences averaged over repeats; **task-clustered paired bootstrap ≥10,000 resamples** (never treat fields, steps or the 1,350 runs as independent); one-sided 95% lower bound > −δ; Holm correction across the ablations; TOST for two-sided equivalence; McNemar on success; report final-answer equivalence rate [C, O].

**Power and the limits of 25 tasks.** n ≈ ((z₀.₉₅ + z₀.₈₀)·σ_d/δ)² = ((1.645 + 0.84)·0.10/0.05)² ≈ 24.7 → 25 tasks give 80% power at δ = 5 pp only if the task-level paired SD ≤ 0.10 (estimate from a pilot) [C]. Zero observed regressions in 25 independent tasks still leaves a one-sided 95% binomial upper bound of 1 − 0.05^(1/25) = **11.3%** on the task-level regression rate; getting that below 2% would take ~149 independent tasks; repeats and correlated fields do not substitute for tasks; hand-picked tasks are not repaired by intervals [O]. Frame the result as "X× faster and Y% cheaper on this task distribution with estimated quality difference Δ in [L, U]" and reserve "lossless" for Tier 1.

**Confound control.** Replayable or self-hosted environments (WebArena-style Docker, record-and-replay proxy), state reset before every run, pinned browser; dated model snapshot IDs and run dates; interleave conditions in time; fix concurrency per condition, log 429s, report wall-clock with and without rate-limit back-off; one region; **one API tier** (never mix standard/fast/flex — OpenAI Fast mode is 2× price and 2.5× speed; Anthropic fast mode has its own rate limit); count speculator/verifier/compressor tokens and calls in cost even when hidden in time; separate cold-start, seen-workflow reuse and unseen-workflow transfer; start each repetition from the same skill/cache corpus; charge learning/compilation/verification; report C_build + N·C_run and the break-even N [C, O].

**Failure handling.** Identical deadlines; timeouts count as failures and keep their time/cost; report all-attempt and success-conditioned latency plus success-within-time curves; common-success subsets are post-treatment diagnostics only; predefine infrastructure-failure rerun rules, keep both records, report sensitivity [O].

**Artifacts.** Scorer code + tests, task manifests, model/provider/version, evaluation dates, reasoning settings, prompts, environment/container versions, task-order seeds, raw traces, usage ledger, aggregate analysis, and the **actual full-project spend** including failed development experiments, distinguishing API bills, hardware inventory, GPU-hours and human labor [O, C].

**Presentation.** Table 1: per model × condition — field F1 (±CI), success, pass^3, wall-clock median (IQR), speedup (geometric mean of per-pair ratios), calls, tokens (in/cached/out), $/run, cost-of-pass. Table 2: non-inferiority results (ΔF1, lower bound, δ, verdict) and trajectory-equivalence audit rates. Figures: cost–F1 and time–F1 Pareto plots with convex hulls per model; stacked per-step latency (LLM / env / hidden); for asynchronous execution, a timestamped critical-path trace rather than summed durations [C, O].

**Checklist mapping.** ABC (empty/default fields score 0; adversarial scorer tests); Miller (clustered SEs, paired differences, power, no temperature games); Kapoor et al. (cost-controlled comparison, simple strong baselines such as retry or a cheaper model alone, standardized logging) [C].

# PART V — Prompt 5: Novelty assessment of the SAP Concur acceleration plan

## 5.1 The plan as described in the prompts (user's own measurements)

Target: LLM agents filing expense reports in SAP Concur, a repetitive enterprise web workflow with a policy-derived, field-level answer key. Both novelty reports (Claude, Gemini) were given the same description; the two headline profile numbers (71% model wait, 57% page-determined) place the setting in Regime A of §1.8, which is where model-side levers have the most headroom.

## 5.2 Verdict (merged)

None of the four components is new on its own; a wave of April–September 2026 preprints sits very close to the plan (Agentic Compilation Apr, SkillDroid Apr, Skim May, Agent JIT May, PANDO May, MFS May, SpeedRunner Aug, SMC Sep, and — added in v2 — **EchoPath Sep 2026**, which already does guarded GUI-trajectory replay with preconditions and a promote/repair/quarantine lifecycle on OSWorld-Verified [C15]). What is still open is narrower and defensible: (i) speculative execution of **state-changing UI transitions on a live SaaS portal that cannot be snapshotted**, with commit/compensation semantics; (ii) **profile-guided recipe compilation with guards and "de-optimize to LLM" fallback**, learned from own runs plus a few demos, on write-heavy multi-page forms, measuring the marginal value of each source; (iii) **field-level accounting of accuracy lost per acceleration lever**, over repeated runs, with latency as a third Pareto axis. Framed as "we combined known tricks on SAP Concur," it reads as an engineering report; framed around the three gaps, measured against the 2026 systems, and extended to public benchmarks, it is publishable [C]. ## 5.4 Done vs open, component by component

**(a) Recipes from own runs + human demos, deterministic replay, LLM fallback — partially done, and narrower after v2.** Done: executable skills induced from own trajectories (ASI, SkillWeaver, SpeedRunner, SkillDroid, PANDO); deterministic blueprints with LLM healing (Agentic Compilation, Hyperbrowser, LOOP); site-profile fast paths with verifier and fallback (Skim); hidden mined macros committed at runtime (SMC); **guarded GUI-trajectory replay with preconditions, bounded parameters, visual re-aiming and a promote/repair/quarantine lifecycle on OSWorld-Verified (EchoPath, Sep 2026)** [C15]; API-first execution that removes the GUI steps altogether (AXIS, ComputerRL, UFO2). Still open: no work combines own-run mining **with** a few human demonstrations and measures each source's marginal value; none calibrates the fallback trigger against a field-level error budget; none evaluates on multi-page, write-heavy enterprise forms with policy constraints; **no work measures replay success across UI versions over time** (EchoPath is a repeat-execution setting against a memory baseline) [C15]; de-optimization semantics (what state the LLM resumes from when a guard fails mid-recipe) are underexplored — Skim's warm start at the fast path's final URL and EchoPath's repair state are the closest [C, G, C15]. Also note ASI's finding that text-only workflow memory does not reliably cut steps (AWM 5.9 vs vanilla 5.6): the "text recipes" ablation is expected to show little efficiency gain, which strengthens the case for executable recipes.

**(b) Speculative execution of predictable UI transitions — done at the tool level; open for stateful live web UIs.** Done: Speculative Actions, PASTE, SMC, Speculate with Memory, AOSpec, DSP, ISP; snapshot/fork substrates (TClone, DeltaBox, SMC). Open: speculation in a live, proprietary, non-forkable SaaS app where server state cannot be snapshotted, which requires (i) restricting speculation to reversible/idempotent transitions (navigation, opening modals, pre-rendering, text entry), (ii) speculating the *observation* (predict the next page so the next model call starts early), or (iii) explicit compensating actions; no paper classifies web UI transitions by reversibility and reports hit rate and accuracy impact in such a portal. This is the most defensible systems contribution and the most likely to be scooped [C, G]. Two v2 additions sharpen it: Speculative Actions proves a **50% latency-reduction cap for single-step speculation**, so the p≈1.0 transitions in Concur should push single-step hit rates toward that cap and *multi-step* (macro-commit-style) speculation is required to exceed it; and every speculative system in doc 15 (SPORK, Speculative Actions, PASTE, DSP) falls back to serial execution for writes — "no paper reports speculative or multi-action execution on a live OSWorld desktop with controlled accuracy measurement" [C15] (with the caveat in D46 that UFO2 and OSWorld 2.0 do report multi-action *batching* results).

**(c) Observation pruning, prefix caching, small-model routing — done.** AgentOccam, FocusAgent, MFS, Agentic Compilation's sanitizer; Skim's small-model extraction; RouteLLM/BoPO/WebRouter; provider prompt caching. Novelty ≈ zero; the only publishable angle is the **interaction**: pruning invalidates caches (AgentDiet notes it), routing interacts with recipe coverage — quantify the interactions rather than the levers [C, G].

**(d) Accuracy–latency–cost frontiers over repeated runs — partially done.** AI Agents That Matter and HAL do 2-D accuracy–$ frontiers; τ-bench introduced pass^k; SpeedRunner reports ±1 s.d. over 3 seeds. No work reports **three-way** accuracy–latency–cost frontiers with **field-level** accuracy for form-filling agents over repeated runs, or attributes accuracy loss to each lever [C].

**The combination and the setting.** The integrated stack on an enterprise portal is not published as a unit; no LLM-agent paper evaluates on SAP Concur or expense reporting with policy-derived keys (closest: TheAgentCompany finance/admin tasks; WorkArena/++ on ServiceNow). Reviewers value the answer-key methodology more than the brand [C].

## 5.5 Baselines, ablations, objections (merged)

**Baselines reviewers will demand.** (1) Vanilla ReAct / Browser-Use / BrowserGym GenericAgent on the same model (the baseline of Agent JIT, Skim, FocusAgent). (2) AWM (text workflows) and ASI or SkillWeaver (programmatic skills as tools); SpeedRunner optional. (3) Pure RPA/scripted replay from demos with no LLM, plus the same with naive LLM fallback (Hyperbrowser / Agentic-Compilation style) — the most dangerous baseline: if a script alone reaches 95% field accuracy at near-zero cost, the contribution is only the residual. (4) Skim-style fast path with verifier and warm-started fallback. (5) Speculative Actions and SMC-style macro commit on equal hardware (SMC reports gains relative to SA; do the same). (6) APC plan caching. (7) Prompt-caching-only, small-model-only, cascade/router-only (FrugalGPT/RouteLLM), each alone. (8) Agent JIT Compilation if code is available, else a re-implementation of its planner. (9) Inference-optimized stateless baseline on SGLang/vLLM APC to isolate infrastructure gains. (10) PANDO and SkillDroid adaptations [C, G]. Added in v2 [C15]: (11) **an API-first / hybrid API+GUI agent** (AXIS-, ComputerRL- or UFO2-style) wherever Concur exposes an API — if it solves most reports, the GUI stack is only for the API-less remainder; (12) **EchoPath-style guarded trajectory replay** with lifecycle management, the closest published recipe system; (13) a **budget-shown ReAct / BATS-style** baseline, since showing the agent its remaining budget alone cut cost 31% at equal accuracy.

**Ablations.** Leave-one-out for (a), (b), pruning, caching, routing; pairwise interactions (caching × pruning; recipes × routing); recipe source (own runs only / demos only / both; 0, 1, 3, 5 demos; number of own runs); fallback-trigger threshold sweep (produces the frontier itself); speculation depth/breadth and reversible-only vs all transitions with hit rate, wasted calls and side-effect incidents; pruning aggressiveness vs field accuracy; N ≥ 5 repeated runs with pass^k and bootstrap CIs on every frontier point; distribution shift (synthetic DOM perturbations, a real Concur release, new policy rules and expense types) with recipe breakage and recovery cost; SpeedRunner-style cost-per-report curves vs number of prior reports including amortized compilation; w/o speculative UI execution (quantifies the 71% model-wait that faster LLMs alone cannot remove) [C, G].

## 5.6 Framings

1. **Profile-guided tiered compilation for agents (JIT with de-optimization).** Interpret with the LLM; detect hot, stable trajectory fragments; compile them into guarded recipes; de-optimize to the LLM on guard failure, resuming from the current state. Venue: MLSys (OSDI/SOSP if the runtime is substantial). Position against Agent JIT (compiles from the instruction, not profiles), Agentic Compilation (no guards/profiling), SpeedRunner/ASI/SkillDroid (skills as LLM-called tools or mobile-only), APC. Distinguishing claim: profile-guided + guard-based de-optimization with measured coverage and mis-speculation cost [C, G].
2. **Branch prediction for stateful UIs: speculative execution without snapshots.** Treat UI transitions as branches; predict and execute (or pre-fetch the observation of) near-deterministic transitions; classify by reversibility with commit and compensation rules. Venue: MLSys or NeurIPS. Position against Speculative Actions (general, lossless), SMC/TClone (need snapshots), PASTE (tools), Speculate with Memory (transition tables), Skim (read-only). Distinguishing claim: safe speculation in live, irreversible web apps with hit-rate and side-effect analysis [C, G].
3. **Where agent time and money go: field-level, three-way Pareto accounting for enterprise automation.** A measurement paper on answer-key-graded workflows decomposing the 13-minute, 100-call run into page-determined vs reasoning steps and reporting per-lever accuracy loss with repeated runs and consistency metrics. Venue: NeurIPS D&B or ICLR; strongest with a released Concur-like environment. Position against AI Agents That Matter, HAL, Efficient Agents (2-D), τ-bench pass^k, WorkArena++ [C]. Gemini's "microeconomics of agentic automation" is the same framing [G].

Recommendation (both providers): lead with 1 + 2 as one MLSys submission and use 3's methodology as the evaluation backbone; 3 alone risks reading as a case study unless an environment is released.

# Appendix B — Glossary of measurement terms used in this dossier

- **Step / turn**: one observe→decide→act cycle against the environment (OSWorld 2.0 uses "steps" in Table 3 and "turns" in the text; batched tool calls put several actions in one step).
- **Tool call**: one action or tool invocation; several per step when batched.
- **Model call**: one LLM request; several per step in planner/judge/reflection scaffolds (GTA1: 4–12 planning calls per judging call).
- **Critical-path depth**: the longest chain of dependent model/tool calls; governs latency under parallel execution.
- **Wall-clock**: request accepted → final committed state, including environment time, tool time, queueing and rate-limit waits.
- **Inference time**: model-only decision time; excludes browser/tool/environment time (Browser Use's 68 s vs 225–330 s).
- **Prefill / decode**: input-processing vs token-generation phases; prefill-bound when uncached contexts grow (OSWorld-Human), decode-bound when caches hold (2605.26297).
- **Cost per attempt / per success / cost-of-pass**: mean $ per attempted task; total $ ÷ successes (pooled); taskwise E[C_i]/p_i.
- **pass^k / pass@k**: probability all k trials succeed / any of k succeeds.
- **WES**: Weighted Efficiency Score — success weighted by step efficiency vs human reference (OSWorld-Human).
- **Lossless (sense 1/2/3)**: by-construction trajectory preservation / statistical non-inferiority within δ / no observed degradation.
- **Regime A/B/C**: latency profiles for screenshot multi-call agents / AXTree single-call web agents / cached coding agents (§1.8).
