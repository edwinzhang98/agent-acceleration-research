# Follow-up 3 — Enterprise RPA + LLM fallback products (dossier §8.3 item 3)

**Date:** 2026-09-27 · **Against:** `Agent-Acceleration-Consolidated-Dossier-v2.1-2026-09-27.md` (E1–E93, D1–D94) · **Scope:** what UiPath, Automation Anywhere, Microsoft Power Automate, Hyperbrowser, Browserbase (Stagehand), Browser Use, Skyvern, Notte ship for record/replay with LLM fallback, plus the three research systems that the dossier already groups under this pattern (LOOP, Activity Frames, Agentic Compilation). The questions were: how failures are detected, how selectors are healed, measured replay success, cost per run, and published latency. **Patch targets:** §5.3 rows 11 and 20, §5.5 baseline (3). The same entries also appear in the §3.1 table, §5.4(a), E87 and §8.1, so there are consistency patches for those too.

**Method.** Vendor documentation is treated as the primary source for *what ships*. Every vendor performance number is labeled **vendor-marketing**. arXiv papers were read at the stated version. For LOOP (arXiv 2605.14237v1, which has no HTML version), the PDF was downloaded and its text extracted locally, so the LOOP quotes are exact. All other quotes came back through the WebFetch tool after asking it for verbatim text. They are marked "(via fetch)" and should be spot-checked by a human before they go on a slide. None of the E-IDs in the dossier covers any of these sources: E87 records Browserbase speed claims as *missing*, and §3.1/§5.3 row 20 mention LOOP, Activity Frames and Hyperbrowser without an E-ID. So all entries below are new (EF3-n). Items from the P0-P1 "New leads" list: none bears on this topic. The Gemini-CU/Browserbase-harness lead belongs to follow-up 6.

**Headline.** Every major RPA vendor now ships the *mechanism*: deterministic replay, then detection of a failure, then an LLM or vision heal, then optionally writing the fix back. Examples: UiPath Healing Agent, Power Automate self-healing, Automation Anywhere Generative Recorder, Stagehand caching, Skyvern code caching and Hyperbrowser HyperAgent. **No vendor publishes a measured heal/replay success rate, a heal latency, or a cost per successful run.** Two vendor numbers were found:
- Automation Anywhere: "over 60%" fewer execution failures, with no definition.
- Stagehand: "as high as ~80%" speedup on a second, cached run, with no task set.

The research systems the dossier cites for "99%" do not measure replay success on UI workflows:
- LOOP replays bash/file tool calls. Its "99% success" is a model, not a measurement.
- Activity Frames stops when a guard fails. It does not hand control to an LLM mid-routine.
- Agentic Compilation never exercised its healing path.
