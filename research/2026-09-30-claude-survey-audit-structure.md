## 1. 421 与 336：85 条差额有完整解释，不是随机丢条目

核查文件：`notes/part3/2026-09-30-self-improvement-survey-mining-zh.md`、同名 HTML；本地 `scratchpad/survey2607/candidates.json`、`screen/screened.json`、`screen/to-read.json`、`screen/reuse-store.json`、`appendix-c.md`。该 scratchpad 的绝对目录为：

`/private/tmp/claude-501/-Users-edwin-projects-agent-acceleration-research/9da59421-1b89-415a-ab67-1c7662772e43/scratchpad/survey2607/`

用分区、标题前缀和年份逐行匹配（标题原表会截断，MemOS 标题有大小写改写；同名 MemInsight 两条按出现顺序匹配），C.1 的 77 行与 C.2 的 259 行全部映射到候选清单，没有无来源行。缺少的 **85 个候选 ID 恰好等于 64 条新读全文清单 + 23 条复用清单 − 2 条仍保留在 C.1 的复用记录**。保留的两条是 L065/WMA、L074/WorldEvolver。没有额外无法解释的遗漏。

因此 `421 − (64+23−2) = 336 = 77+259`。原始独立文件 `appendix-c.md` 也采用这个结构，差额不是 HTML 转换造成的。最准确的表述是：**深读/复用主条目被从摘要细表中省略，但附录没有明确写出这一排除规则，也没有提供85条的单独对照表**。不能仅展示“421条候选筛选”并让读者以为下方336行就是421条完整明细。

汇总表的“读全文或复用”合计104，是候选条目数，不是104篇论文；它可拆为被移出细表的85行，加细表仍保留的19个“复用/读全文”标记（C.1 4个，C.2 15个）。其中存在同一论文多个目录条目的情况。

另有一个小型状态不一致：汇总为104/222/95（深读复用/摘要/略过），而细表标签与省略项合起来为104/227/90。差5条都在C.1：L034、L042、L070、L075、L076，在 `screened.json` 为 `skip`，细表却统一标“摘要”。这不改变421总数，但应统一“筛选处理”和“实际读了摘要”的含义。

## 2. 88条书目与82篇合格引用：算术自洽，阅读数量的叙述混用了单位

参考文献恰有 **88个唯一记录号**，其中综述s000一条，暂缓/排除s019、s023、s032、s053、s046五条，因此 `88−1−5=82`。**“正文参考文献中82篇合格的非综述论文”这一口径自洽。**

但不能据此认证“64篇新读+23篇复用=87篇去重全文，减5=82”这条阅读流水账：

- `to-read.json` 有64个s记录；`reuse-store.json` 有23个候选条目，其中 L237 与 X370 都是 Darwin Gödel Machine，只对应22篇不同工作。
- Reference 的88条实际构成为63个s001–s064记录、24个旧记录号、s000；新读的 **s057/SAGE: Self-evolving Agents with Reflective and Memory-augmented Abilities** 在台账与 `part3-records-s.md` 中有全文、合格记录，却没有进入报告Reference，也没有在附录细表留下它的主条目X383。
- Reference里的旧记录还包括Self-Refine/h018与SEAgent/w022，它们不在最初23条 `reuse-store.json` 清单中；报告另提及已读的WebRL但未引用。可见初始阅读计划、已读范围和最终引用集合不是同一集合。

这里的s057不是“参考文献漏引了正文使用的论文”（本轮未发现正文使用它），而是**已读但未引用的合格论文没有在最终读者索引里列明**。建议把“读过的记录数”“去重读过的论文数”“正文实际采用的合格论文数”分别陈述。82可作为最终采用的非综述合格书目数保留；“87篇全文”及“23篇复用”的去重解释应重算，不要继续直接相加。

## 3. 核读版本截断：能定位论文，不足以保留完整审核语境

88条书目均有实际核读版本链接；其中 **55条链接标签含省略号**，另有 **8条书目/会议信息说明在版本段之前含截断**。本轮字符串检查未发现这88个实际核读URL本身被截断；其中arXiv链接均明确带版本号。因而读者通常仍可打开对应版本，这一点足以支持基本的论文定位。

HTML保留了这些URL和原标签，构建器还给每条书目单独的“实际核读版本”入口。保留截断并明示限制，作为忠实阅读版是合理的；**不能将其称为已经恢复了完整核读记录或完整发表确认信息**。被截掉的内容可能包括HTML缺图时是否补看PDF、另一版本是否对比、正式发表是否核实等。例：s063版本标签止于“PDF v2 t…”，s028止于“anchors r…”，无法从这一标签恢复完整核验路径。

附录A摘要截断的问题比书目更直接：HTML确实从仓库台账补了完整陈述、条件和原文位置，比仅保留原稿摘要好。但原始引用锚点、逐行全文及421条完整筛查JSON仍在仓库外的临时核对库；`part3-records-s.md`也说明锚点不随文档导出。**带本地行号不等于离开这台机器仍能复现核查。** HTML当前未链接两个仓库证据文件本身；内嵌台账字段可以查陈述，不能替代完整原始审计材料。

## 4. 阅读版最小修补建议

1. 筛查页明确写：“421条候选总账；此处336条摘要细目，另85条深读/复用主条目移至正文/证据记录；目录条目并非独立论文。”最理想是加一份带CID、处理、论文统一ID、记录号/证据链接的421行机器表；不要声称现有细表已逐条展示421条。
2. 书目计数明确为“88条=82条合格非综述引用+综述1条+暂缓/排除5条”；阅读数量另列，不从这88条反推全部已读工作。为s057等已读未引用工作保留简短状态索引。
3. 核读标签截断继续显式提示；现有有版本URL应保留。补可持续访问的台账/记录文件链接，或导出完整版本描述与本轮核验条件，不能凭省略号自动猜补。
4. 上述是原稿的信息组织风险，不是HTML擅自删掉85条的转换错误；修补时应标为阅读说明或审核说明，避免误报为内容丢失。
