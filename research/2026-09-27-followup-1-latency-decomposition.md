# Follow-up 1 — Latency decomposition by architecture (dossier §8.3 item 1)

**Date:** 2026-09-27 · **Base:** `Agent-Acceleration-Consolidated-Dossier-v2.1-2026-09-27.md` (E1–E93, D1–D94) · **Patch targets:** §1.2, §1.8 · **Provisional IDs:** EF1-1…EF1-19, DF1-1…DF1-7

**Scope.** Every published per-step or per-request latency breakdown for (A) screenshot-based computer-use agents, (B) AXTree/DOM/text web agents, (C) cached long-session coding agents. Each breakdown is placed in one of the three regimes of dossier §1.8, with its dominant term. Where a workload fits none of the three cleanly, it is placed in the closest regime and marked **misfit**.

**Method and access log.** 38 WebFetch calls, 6 WebSearch calls, 4 GitHub code searches. arXiv HTML read at the version given in each row. Failures: BrowserGym v4 HTML ends before Appendix G (tried twice) and its PDF exceeds the fetch size limit, so E26 was **not re-verified**. UFO2 HTML v1 and v2 both cut off before Fig. 24; the v2 PDF (4.2 MB) was saved and its text extracted locally with pypdf, but the Fig. 24 bar values are vector glyphs and cannot be read as text. openai.com returned 403, and the developers.openai.com docs page was used instead. Quotes marked "(fetch-tool quote)" came through the WebFetch summariser, which was asked to return verbatim text. They are verbatim as returned but were not seen character-for-character by me. Rows with no quote marks are paraphrases and are labelled as such.

**Legend.** Regime A = screenshot-based, multi-call desktop agents. Regime B = text/AXTree/DOM single-call web agents. Regime C = cached, append-only long-session tool agents (coding). "Dominant term" is the component with the largest share of the measured time in that breakdown. NR = not reported.
