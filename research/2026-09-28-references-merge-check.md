# 2026-09-28 — Merge check of PR #1: ledger-wide reference list vs the curated deck list

Trigger: Edwin asked to merge PR #1 (`claude/slide-references-l1mof9`: `slides/references-ledger.md`, `slides/references.bib`, `slides/check_references.py`) and to check it, expecting the ledger's verification to be the stronger one. The branch had already merged main and renamed its list, so the git merge was clean (`slides/references.md` untouched, check 0 failures). This file records the content check of the two lists against each other and against primary sources.

Method (all read 28 Sep 2026): arXiv export API (authors in order, comment, journal-ref, latest version) for all 83 arXiv IDs in `slides/references.md`; the schema.org record on the ICML/ICLR/NeurIPS virtual pages and Crossref DOI metadata for the ledger's class-A entries (50 of 78 are machine-readable this way); the TMLR accepted-papers list (https://jmlr.org/tmlr/papers/) and its per-paper BibTeX; PMLR for ICML 2024; vldb.org for PVLDB vol. 20; the arXiv HTML title blocks of OSWorld 2.0 and Continuum. OpenReview's API answered 403 and DBLP showed a bot wall, so neither was used. No numbers were re-measured; this pass is about who wrote what and where it appeared.

Result: the ledger is right wherever it read a venue page (50 of 50 author lists and titles match the ICML/ICLR/NeurIPS/Crossref records). In the 27 rows below it is right outright on 16 and on the venue but not the author order on 2 more; its TMLR entries took the arXiv author lists instead of the TMLR ones (BrowserGym, FocusAgent, UFO2), and six author names were venue-page account names. The curated list was behind on published versions (six author lists followed arXiv where the published version differs), had five author orders that match no version and two wrong titles, and was wrong on Continuum's venue: its PVLDB reading of a template header breaks its own rule (D150).
