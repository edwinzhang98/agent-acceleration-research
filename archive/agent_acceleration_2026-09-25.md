# Agent acceleration: research landscape, 2023–2026
As of 25 September 2026. Selected primary-source literature, with emphasis on web, GUI, computer-use and long tool workflows. Numbers refer to the linked paper versions, not to today's leaderboards or API prices. These are reported results, not independent reproductions.

The central finding is that reducing repeated planning, replacing GUI sequences with programs, and exploiting tool/model concurrency can yield substantial gains. However, exact output-preserving acceleration, empirical accuracy preservation, and an acceptable accuracy trade-off are different claims.

**Legend:** **L** = lossless only under stated execution/verification assumptions; **E** = empirical non-degradation at the quoted operating point, not a guarantee; **X** = observed accuracy loss; **NR** = numerical result not reported or not verified; **N/A** = benchmark/metric, not an accelerator. “pp” denotes percentage points. Steps, tokens, FLOPs and throughput are not interchangeable with end-to-end latency. Ratios calculated from quoted raw values are identified as calculations.

This is the agentic-RPA direction: a successful trajectory becomes a parameterized program with explicit execution checks. Program reuse can eliminate reasoning calls, but compiling a brittle demonstration is insufficient without preconditions, postconditions and recovery.

For a serious comparison, report task success with uncertainty, end-to-end median and tail latency including failures, all-in cost, and the cost–accuracy–latency frontier. Also report model calls/actions, tool wait, prefill/decode, cache state, hardware/concurrency, and cold versus warm performance. Cost-of-pass should be calculated at the appropriate problem level; a ratio of aggregate means can conceal heterogeneous failure probabilities.

## What remains open

1. **Verified program reuse under drift.** Screens, hidden application state, permissions and user data change. A replay mechanism needs actionable failure detection and recovery, not merely a script that exits successfully.
2. **Amortization.** Skill discovery, demonstrations, compilation, verification and memory maintenance are real costs. For a fixed reuse distribution, a basic break-even estimate is setup cost divided by per-task savings; include cache misses, invalidation and failed replays.
3. **Speculation with irreversible effects.** Read-only search is easier than sending a message, submitting an order or changing a shared record. Exact action equality alone does not establish that two executions saw equivalent state.
4. **Adaptive action granularity.** Determine when several GUI actions can execute before another observation, and when to stop for a screen check. This couples batching, grounding, reasoning budgets and recovery.
5. **Joint optimization.** Prompt compression can destroy reusable prefixes; an extra router or verifier can erase latency savings; speculative branches can increase GPU/API cost. Individual paper speedups should not be multiplied.
6. **Agent-level non-inferiority.** Equal point estimates or non-significant differences are weak evidence. Long tasks need repeated trials, held-out workflow templates, state perturbations and field-level correctness, including errors that the final benchmark check misses.
7. **Critical-path and deployment realism.** Shared-server throughput, token savings and successful-task latency do not directly answer how long a real user waits. Tail delays, tool variance, timeouts, human repair and contention remain insufficiently measured.

These are synthesis judgments grounded in the limitations above, not claims of a newly measured ranking.

## Verification limitations

- Conference labels are used where primary metadata or proceedings were found; otherwise entries are labeled arXiv. This is a selected landscape, not an exhaustive census of every named venue.
- **Log2Plan:** time and success are transposed between table and prose; unresolved.
- **FocusAgent:** use the August 2026 revision's main table; its appendix retains older values. Input-token cost is not the complete bill, and its latency study uses a smaller task subset.
- **AutoDroid-V2:** raw section-level inference times imply a ratio outside the introductory range; retain raw values.
- **TPS-Bench:** final ACL table and abstract disagree; this report explicitly uses the table.
- **OS-Catalyst:** mechanism and indexed claims found; exact matched timing configuration and acceptance not verified. It is a pointer, not a trusted quantitative result.
- Several serving papers omit task-quality measurements. **NR does not mean a measured zero accuracy loss.**
