# Agent Acceleration: Mapping LLM Inference Optimizations to Agent Workflows

**Research cutoff: September 25, 2026**

## Main finding

**The useful shift is from optimizing token generation to optimizing the critical path of a successful task.** Agent acceleration can eliminate, reuse, overlap, or cheapen entire decisions. However, behavioral equivalence, comparable benchmark accuracy, and an accuracy–cost tradeoff are different claims.

Below, the cutoff is **September 25, 2026**. Gains retain their original workload and baseline; the open-problem column is my synthesis. “Per request,” “per action,” throughput, and end-to-end latency are deliberately distinguished.

## From token cost to dependent decisions

**The cost unit expands from tokens to dependent decisions—but tokens still determine much of the bill.** Three observations make that distinction concrete:

- **One environment step can contain several expensive model calls.** OSWorld-Human’s S2/GTA1 profiling attributes **87.03%** of S2 time to planning plus reflection, and **97.12%** of GTA1 time to planning plus judging. Its illustrated S2 task takes **50 steps and over 40 minutes**: **over 48 seconds per step**, calculated for that example, not a benchmark-wide average. GTA1 can make **4–12 planning calls per judging call**, plus grounding. Consequently, action count, model-call count, and sequential depth require separate measurements. ([arxiv.org](https://arxiv.org/html/2506.16042v2?utm_source=chatgpt.com))
- **Production requests expand into mostly sequential inference chains.** *Agentic Coding in the Wild* reports **6.6 mean model calls per user turn** in GitHub Copilot telemetry, with median intra-turn concurrency only **1.15**. The reported **15 median / 40.6 mean calls per session** concern multi-turn sessions, not individual tasks. This makes repeated request entry and dependency depth material serving costs. ([arxiv.org](https://arxiv.org/html/2608.00101v1?utm_source=chatgpt.com))
- **Growing context creates repeated logical input, but not necessarily repeated prefill.** OSWorld-Human observes later steps taking up to **3× longer** as history accumulates. Conversely, *Agentic AI Workload Characteristics* finds **84.6–99.5% cache hits** and **91.0–98.6% of LLM time in decoding** when KV state remains resident without thrashing. Therefore, “agents are prefill dominated because prompts are large” is not a universal conclusion. ([arxiv.org](https://arxiv.org/html/2506.16042v2?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2605.26297v1?utm_source=chatgpt.com))

## Context growth and task-level accounting

A simple accounting model clarifies the mechanism. For \(N\) model calls, with initial context \(H_0\) and \(\Delta\) additional tokens per call, the **logical submitted input volume** is

$$
\sum_{i=1}^{N} H_i
=
NH_0+\frac{\Delta N(N-1)}{2},
\qquad H_i=H_0+(i-1)\Delta.
$$

This is an algebraic model of context replay, **not a claim of universally quadratic runtime**. Effective caching avoids re-prefilling unchanged prefixes, while decoding still accesses growing KV state; eviction or context rewriting can restore recomputation costs. *SmoothAgent* explicitly studies the latter: context transformations invalidate cached prefixes and cause latency spikes. ([arxiv.org](https://arxiv.org/html/2605.26297v1?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2607.00151v1?utm_source=chatgpt.com)) For a serial workflow, task time accumulates queueing, prefill, decoding, tools, and orchestration across calls; with parallel execution, the dependency graph’s **critical path** governs completion. Dollar accounting must separately retain uncached-input, cached-input, output, and tool charges. Thus, useful evaluation reports **task success, calls, dependency depth, end-to-end latency, and total cost together**—the AWO counterexample shows why call count alone is insufficient. ([arxiv.org](https://arxiv.org/html/2312.04511v3?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2601.22037v2?utm_source=chatgpt.com))

## Single-slide thesis

**Single-slide thesis:** Agent acceleration is inference optimization lifted to a stateful execution graph: speculate future transitions, retain reusable computation, compile familiar routines, schedule independent work, and allocate model capacity according to decision difficulty. The research objective should be **lower wall-clock time and dollars per successful task at a specified reliability level**. Existing papers validate these mechanisms separately; the remaining opportunity is their joint control under changing environments, limited KV memory, and imperfect confidence. PASTE demonstrates why integration matters: accelerating tools alone creates returning-request congestion, whereas coordinated tool and LLM scheduling delivers the task-level gain. A successful system must choose when to reason, when to reuse, and when to verify using the cost of the entire remaining workflow. ([arxiv.org](https://arxiv.org/html/2603.18897v3?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2511.02230v7?utm_source=chatgpt.com), [arxiv.org](https://arxiv.org/html/2604.27151v1?utm_source=chatgpt.com))
