# Agents get faster by calling models less

Agent research in 2025–2026 converges on one finding. The quickest way to make web, GUI and computer-use agents faster and cheaper is to **cut the number and size of LLM calls, not to speed up each call**. On OSWorld, LLM planning and reflection take **76–96% of end-to-end task latency**, and the best agents take **2.7–4.3x more steps than a human needs** ([OSWorld-Human](https://arxiv.org/html/2506.16042v2)). The methods that reduce calls turn out to lose the least accuracy. Executable skills, site-derived tools and native APIs cut steps by 10% to 3x and usually *raise* success rates ([ASI](https://arxiv.org/html/2504.06821), [WALT](https://arxiv.org/html/2510.01524v1), [ComputerRL](https://arxiv.org/html/2508.14040)). Serving-layer work (exact KV reuse, tool-pause-aware scheduling) and provider prompt caching give 1.6x–15x throughput and 41–80% lower API cost without changing outputs ([SGLang](https://arxiv.org/abs/2312.07104), [Autellix](https://arxiv.org/abs/2502.13965), [Don't Break the Cache](https://arxiv.org/abs/2601.06007)). Swapping in smaller models, pruning observations, and sharing KV approximately all cut cost further but trade away some accuracy. Speculation is lossless by construction, but its reported gains are only 10–48% of latency, and it has not yet been applied to irreversible GUI clicks. The main weakness across the field is measurement: papers report steps, tokens, FLOPs or dollars on incompatible benchmarks, so cross-family comparisons remain rough.

## Executive summary

- **Fewer calls is the biggest lever, and it tends to be lossless or better.** Programmatic skills (ASI: [10.7–15.3% fewer steps, +23.5% relative success on WebArena](https://arxiv.org/abs/2504.06821)), site-derived tools (WALT: [1.3–1.4x fewer steps](https://arxiv.org/html/2510.01524v1)) and API+GUI action spaces (ComputerRL: [at most 1/3 the steps of the strongest baseline](https://arxiv.org/html/2508.14040)) all improve accuracy as well as speed. Text-only workflow memory does not reliably save steps: in ASI's re-run, AWM took [5.9 steps vs 5.6 for vanilla](https://arxiv.org/html/2504.06821).
- **Planning dominates latency.** On OSWorld, planning and reflection take [76–96% of latency](https://arxiv.org/html/2506.16042v2), and in one profile planning was [87% of a $2.43/task bill](https://proceedings.mlsys.org/paper_files/paper/2026/file/5edb57c05c81d04beb716ef1d542fe9e-Paper-Conference.pdf). Grounding costs almost nothing by comparison, so methods that remove or batch planning calls matter most.
- **These speedups are lossless:**
  - exact KV and prefix reuse in serving engines (SGLang [up to 6.4x throughput](https://arxiv.org/abs/2312.07104); InferCept [1.6–2x](https://arxiv.org/abs/2402.01869); KVFlow [up to 2.19x](https://arxiv.org/abs/2507.07400)) and program-level scheduling (Autellix [4–15x throughput at equal latency](https://arxiv.org/abs/2502.13965));
  - provider prompt caching ([41–80% lower API cost](https://arxiv.org/abs/2601.06007));
  - running independent tool calls in parallel. LLMCompiler reports [3.7x latency and 6.7x cost gains with ~9% *higher* accuracy](https://arxiv.org/abs/2312.04511). Its planner differs from ReAct's, so the end-to-end result is "better", not bit-identical;
  - speculation that commits only on an exact match (SPORK, Speculative Actions, DSP).
- **These speedups are lossy:**
  - model swaps and routing (Fara-7B, RouteLLM, step-level cascades);
  - observation pruning (FocusAgent: [−4.2 pp on WebArena for 59% fewer tokens](https://arxiv.org/html/2510.03204v1));
  - approximate cross-agent KV sharing (KVCOMM, DroidSpeak; both report "zero"/"negligible" loss on selected tasks);
  - plan caching (APC: [96.61% of optimal accuracy](https://arxiv.org/html/2506.14852v2)).
- **Small specialized computer-use models give the largest cost cuts.** Fara-7B costs [$0.025 vs $0.913 per WebVoyager task against OpenAI computer-use-preview, at 73.5% vs 70.9% success](https://arxiv.org/html/2511.19663v1). It still trails on harder benchmarks ([34.1% on Online-Mind2Web](https://arxiv.org/html/2511.19663v1)).
- **Reasoning budgets should be adaptive, not uniformly cut.** Per-step effort routing saves ~35% of tokens with 0 to −1.8 pp accuracy (Ares, [arXiv](https://arxiv.org/html/2603.07915)). Uniformly low effort drops ~20 pp on TAU-Bench Retail ([Ares](https://arxiv.org/html/2603.07915)). HAL found higher effort gave equal or lower accuracy in [21 of 36 settings](https://arxiv.org/html/2510.11977).
- **Efficiency is now a first-class evaluation axis.** OSWorld-Human (MLSys 2026), Cost-of-Pass (ICLR 2026), HAL (ICLR 2026) and AI Agents That Matter (TMLR 2025) are the main examples. There is still no shared "LLM calls or dollars per successful task" metric.

## 1. Fewer model calls: code and APIs replace click chains without hurting accuracy

The saving scales with how much work each abstraction absorbs. Chunking primitive clicks into skills saves roughly 10–15% of steps. Tools derived from site functionality save 1.3–1.4x. Native APIs save up to 3x in steps, or 65–70% of task time. Compiling a whole task into a verified code plan reports ~10x, on a small sample.

Agent Workflow Memory (AWM, ICML 2025) set up the skill line. It reports [+51.1% relative success on WebArena](https://arxiv.org/abs/2409.07429) and says it reduces steps, but gives no number. **ASI's controlled re-run found AWM used *more* steps than vanilla (5.9 vs 5.6)** ([ASI](https://arxiv.org/html/2504.06821)). Text workflows guide the agent but do not replace its calls; executable skills do. Other works in this family:
- Beyond Browsing (CMU, Findings of ACL 2025): a hybrid API/browsing agent reaches [38.9% on WebArena, +24.0 pp over browsing alone](https://arxiv.org/abs/2410.16464). Its step reduction is ⚠ unverified.
- SkillWeaver (⚠ venue unverified): [+31.8% relative on WebArena, and up to +54.3% when weaker agents use APIs made by stronger agents](https://arxiv.org/abs/2504.07079). It reports no step figures.
- Agentic Compilation, a single-author industry preprint: one LLM call compiles a JSON workflow that replays with zero further calls. Its ["1500x" cost reduction](https://arxiv.org/html/2604.09718) is a modeled projection over proprietary enterprise DOMs, with [80–94% compilation success](https://arxiv.org/html/2604.09718). Treat it as weak evidence.
- ECLAIR (Stanford Hazy Research, PVLDB 2024) is the canonical "foundation models replace RPA" paper. It reaches [93% on workflow understanding and 40% end-to-end completion](https://arxiv.org/abs/2405.03710), but keeps the LLM in the loop on every run, so it reports no cost reduction.

## 2. Caching and reuse: savings scale with how repetitive the workload is

All cross-task caching is lossy in principle, because a matched artifact replaces fresh reasoning. The exception is exact tool-result caching, which is lossless only when tool outputs are deterministic and fresh. Near-duplicate workloads save about 90%; heterogeneous reasoning saves about 25–50%.

Plan-level caches (APC, AgentReuse) still need an LLM on hits. Action-level replay (EchoPath, AppAgentX) can skip the LLM entirely, which gives larger savings but is more fragile when the UI changes. APC's paper also shows that embedding-similarity semantic caches lose accuracy through false-positive hits ([APC](https://arxiv.org/html/2506.14852v2)). Two adjacent works:
- AWO mines recurring tool-call sequences into deterministic meta-tools: [11.9% fewer LLM calls, +4.2 pp success](https://arxiv.org/abs/2601.22037). Its affiliation is ⚠ unverified.
- AgentRR proposes record-and-replay with "check functions" but gives [no quantitative results](https://arxiv.org/abs/2505.17716). Its authors are ⚠ unverified.

## 3. Speculation: lossless by construction, capped near 50% per step

Speculation spends extra compute to save latency. A fast predictor (a draft agent, mined patterns, or the target model itself) proposes the next plan step or tool call, and the result is committed only if the authoritative agent agrees. UFO2's speculative multi-action execution is covered in Family 1.

Every system restricts speculation to read-only or reversible calls. None reports speculative GUI actions on OSWorld or WebArena. AAPT, which reports a stated AAAI 2027 venue (⚠ unverified), sidesteps the problem: it pre-compiles a guarded policy tree during idle screen time and lifts success on a 650 ms-window task from [50% to 79%](https://arxiv.org/html/2607.28399), with "nothing executed speculatively". A separate LLNL/UMD preprint (⚠ affiliations unverified) reports ["several hundred tokens per second"](https://arxiv.org/abs/2512.15834) throughput gains from engine-resident speculative tool calls.

## 4. Parallelism and batching: mature for tools, still early for GUIs

Running independent tool calls in parallel is mature and now a standard API feature. GUI tasks are mostly sequential on one screen. Gains there come from emitting several actions per planning call, or from spreading work across several desktops. OSWorld-Human (Family 8) gives the key evidence: human grouped-action trajectories need [4.5 steps vs 13.2 single-action steps on LibreOffice Calc](https://proceedings.mlsys.org/paper_files/paper/2026/file/5edb57c05c81d04beb716ef1d542fe9e-Paper-Conference.pdf).

No controlled study was found that measures how success changes when a computer-use agent emits k>1 GUI actions per call on OSWorld. Acting without re-observing the screen risks acting on stale state, the same irreversibility problem speculation faces.

## 5. Cheaper calls: small models give order-of-magnitude savings, pruning costs a few points

Ranked by cost-cutting power: specialized small models (about 10–36x), prompt caching (2–5x on input, lossless), observation pruning (about 2x fewer tokens, small losses), then visual-token pruning (1.4–3.4x compute). High-resolution zoom-in is the counterexample: it spends extra calls to buy accuracy.

- AgentDiet (FSE 2026) trims useless and expired content from coding-agent trajectories: [39.9–59.7% fewer input tokens and 21.1–35.9% lower cost at the same performance](https://arxiv.org/abs/2509.23586). This lossless context compression belongs here, not under reasoning budgets.
- Provider pricing explains why caching pays. Anthropic cache reads cost [0.1x base input as standard](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). OpenAI discounts cached input ["up to 90%"](https://developers.openai.com/api/docs/guides/prompt-caching).
- The Efficient GUI Agents survey quotes further numbers (Aguvis −70% tokens/step, GUI-KV, ST-Lite 1.40x end-to-end, ActionEngine $0.71→$0.06) ([survey](https://arxiv.org/html/2609.02309)). These are ⚠ unverified against the primary papers.

## 6. Serving systems: exact KV reuse gives up to 15x throughput at no accuracy cost

Serving-layer gains come from keeping and reusing KV state across the many calls, pauses and agents in a workflow. Exact reuse is lossless by construction. Quality risk is concentrated in approximate cross-context or cross-model sharing. Headline numbers use different baselines and workloads, so they should not be compared directly. None of the systems below was evaluated on a GUI/computer-use workload in the sources reviewed; their workloads are ReAct, SWE, BFCL and multi-agent pipelines.

## What remains open: measurement, drift and irreversible actions

**Measurement is the most basic gap.** Papers report local savings in tokens, actions or module latency, while benchmarks "often stop at success rate" ([Efficient GUI Agents survey](https://arxiv.org/html/2609.02309)). No study found in the notes compares families (skills vs. APIs vs. speculation vs. routing) on one benchmark with shared cost accounting. OSWorld-Human's WES and cost-of-pass are the leading candidates for a standard.

**Reuse under drift is the next gap.** Skills, caches and compiled workflows run deterministically, so stale or wrong entries act without LLM oversight. ASI notes that skills need adapting when interfaces change ([ASI](https://arxiv.org/abs/2504.06821)). EchoPath's lifecycle management (promote, repair, quarantine) is the most developed answer ([EchoPath](https://arxiv.org/html/2609.16635)). No work measures replay success over UI versions across time. Poisoning of shared caches is also unstudied; key-collision attacks on semantic caches already exist ([arXiv 2601.23088](https://arxiv.org/html/2601.23088v1)).

**Irreversible GUI actions block speculation and batching.** Every speculative system falls back to serial execution for writes ([SPORK](https://arxiv.org/html/2607.03333), [Speculative Actions](https://arxiv.org/html/2510.04371v2)). No paper reports speculative or multi-action execution on a live OSWorld desktop with controlled accuracy measurement.

**Techniques are rarely tested in combination, and some interfere.** Observation pruning changes the prompt prefix and so can break prompt caching. No paper quantifies this interaction ([Don't Break the Cache](https://arxiv.org/abs/2601.06007) shows naive caching can even raise latency). Per-step routing, pruning and caching have not been evaluated together end to end.

**Budget control has not been solved jointly.** Research treats the thinking budget and the action budget separately ([TTI](https://arxiv.org/html/2506.07976), [BATS](https://arxiv.org/html/2511.17006)). Learned effort routers have been shown only on small open models ([Ares](https://arxiv.org/html/2603.07915)). Vendor effort knobs lack same-model ablations on agent benchmarks.

## Conclusion

The field has quietly redefined "agent acceleration". In 2023–2024 it mostly meant faster tokens: parallel calls and KV reuse. By 2025–2026 it means **making fewer decisions at all**, by turning experience into code, tools, caches and API calls that execute deterministically. That shift explains why the biggest wins in this survey are also the most accurate: deterministic code does not compound errors the way repeated LLM calls do. The cost is a new class of risk. Stale skills, poisoned caches and irreversible actions run without a model checking them, and verification and lifecycle management (EchoPath's quarantine, JIT's pre/postconditions, speculation's read-only guards) are becoming the core research problem.

For practitioners, the families stack. Lossless layers come first because they are free: exact KV reuse in serving, append-only prompts for provider caching, and parallel execution of independent calls. Next come call-count reducers (skills, APIs, grouped actions), which tend to improve accuracy. Lossy levers (small-model routing, observation pruning, lower effort) go last, tuned per step rather than applied uniformly. No paper has measured the full stack end to end on a computer-use benchmark with dollars and wall-clock time. Whoever does will likely set the field's next reference point.
